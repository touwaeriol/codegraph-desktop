# UI 设计

状态：首版界面已按本规格实现并通过前端构建，真实桌面联调仍待完成；日期：2026-10-03。实际验证范围见 [验证记录](05-validation.md)。本文中的线框仍为设计示例。

## 1. 设计目标

用户打开应用后应能立即判断：当前选中哪个项目、实例是否运行、索引是否可用，以及两个 AI 客户端是否真正接入。

首版采用中文、浅色优先、工具型桌面布局。项目列表持续可见，操作集中在当前项目，不使用装饰性仪表盘或没有实际来源的统计图。

## 2. 信息架构

```text
应用
├─ 项目工作台
│  ├─ 左侧：项目搜索、筛选、添加、列表
│  └─ 当前项目
│     ├─ 概览：实例、索引、最近活动
│     ├─ MCP 配置：Codex、Claude Code、差异、测试
│     └─ 运行日志：级别筛选、暂停滚动、导出
├─ 添加 / 编辑 / 重新定位项目
├─ 配置预览与恢复
├─ 设置：CodeGraph 入口、任务并发、关闭行为
└─ 托盘：显示窗口、停止全部、退出
```

“全部项目”在侧栏摘要中显示总数及运行数，不另建重复仪表盘。项目详情标签切换时保留当前项目与滚动位置。

## 4. 视觉规范

### 4.1 色彩

- 应用背景：`#F5F6F8`。
- 内容面：`#FFFFFF`；侧栏：`#EFF1F4`。
- 主文字：`#19212B`；次级文字：`#5D6876`。
- 结构边框：`#DCE1E7`。
- 主操作：`#176B52`，白色文字；hover：`#125640`。
- 成功文本：`#176B52`，淡底：`#EAF5EF`。
- 警告文本：`#875B00`，淡底：`#FFF4D6`。
- 错误文本：`#B42318`，淡底：`#FEECEB`。
- 焦点描边：`#2563EB`，2 px，不能只靠颜色表达状态。

每个状态同时显示图形和文字。禁用态不能与已停止状态混为一谈。正式实现后验证文字对比度达到 WCAG AA。

### 4.2 字体与间距

- 正文使用系统字体，Windows 优先 Segoe UI / Microsoft YaHei UI。
- 路径、端口、代码与日志使用 Cascadia Code / Consolas / monospace。
- 项目标题 24/32 px，分区标题 16/24 px，正文 14/22 px，辅助信息 12/18 px。
- 基础间距 4 px；常用间距 8、12、16、24、32 px。
- 按钮高度 36 px，输入框 36 px，触控目标至少 32 px。
- 面板圆角 10 px、输入框和按钮 6 px；阴影仅用于浮层，不铺满页面。

### 4.3 组件边界

实现拟采用 Tailwind CSS、shadcn/ui 与 Lucide 图标。以组件组合实现表单、Dialog、Tabs、DropdownMenu、Tooltip、Alert 和 ScrollArea；状态展示与日志列表为业务组件。组件依赖版本在脚手架阶段锁定。

建议业务组件：ProjectSidebar、ProjectHeader、RuntimePanel、IndexPanel、ClientConfigPanel、ConfigDiffDialog、TaskBanner、LogViewer、EnvironmentSettings。

## 5. 关键页面与交互

### 5.1 空项目与环境未就绪

没有项目时主区域展示“添加一个项目，开始管理它的 CodeGraph”，主按钮“选择项目目录”，附带简短三步说明。

没有检测到 CLI 时显示独立提示“未找到 CodeGraph”，提供“选择安装入口”和“查看官方安装说明”。仍可添加项目，启动和索引按钮禁用并说明原因。不能把环境错误呈现为空项目列表。

### 5.2 添加项目

弹窗宽 580 px：

```text
添加项目
项目目录  [D:\work\payment-service                ] [选择目录]
显示名称  [payment-service                                    ]
备注      [可选                                               ]
□ 应用启动时自动启动此项目

添加后可初始化索引并配置客户端。
                                      [取消] [添加项目]
```

选择目录后默认填入文件夹名；名称允许修改，路径通过原生选择器或完整路径输入。提交前检查真实目录、重复登记及目录权限。

重复项目提示“此目录已添加”，提供“定位已有项目”。嵌套目录提示可能重复索引，可继续。用户取消目录选择不产生错误 Toast。

### 5.3 项目概览

展示三个相互独立的分区：

1. 实例：状态、运行时长、PID、端口、连接会话数、启动入口版本。
2. 索引：状态、文件数、符号数、最近获取时间。只展示上游实际提供的字段；无字段则省略或显示“未提供”。
3. 客户端：配置状态、已识别连接数、最近测试结果及时间。

主操作随状态变化：

- 已停止且索引可用：启动实例。
- 未初始化：初始化索引。
- 启动中：显示启动中，提供取消启动。
- 运行中：停止实例；重启位于相邻次级按钮。
- 停止中：显示停止中，禁用重复操作。
- 运行错误：重试，旁边提供查看日志。

“同步”和“重建”在运行中会造成维护断连，应弹出简短确认，说明结束后将恢复运行。普通停止无连接时直接执行；有客户端连接时说明受影响会话后确认。

### 5.4 MCP 配置页

```text
MCP 配置                         [测试连接] [预览并配置]
当前项目：payment-service
客户端将共用此项目的 CodeGraph 实例。

☑ Codex
  项目文件：.codex/config.toml
  配置：未配置    会话：未连接

☑ Claude Code
  项目文件：.mcp.json
  配置：已配置    会话：1 个连接

连接方式：客户端 HTTP → 当前项目网关 → 当前项目 CodeGraph
项目服务名：codegraph       [复制]

客户端可能要求信任项目或批准 MCP；写入配置后重新加载客户端。
```

客户端名称来自握手 `clientInfo` 时标注为客户端自报信息；无法识别时显示“未知客户端会话”，不能凭配置文件存在推断已连接。

服务停止时允许生成配置；测试按钮解释“需先启动实例”。配置文件无效时显示解析错误与文件位置，不能静默将其当空配置覆盖；用户可明确进入覆盖预览，再选择编辑全文修复。

0.1.1 起，每个文件支持合并、覆盖整个文件、编辑全文三种方式。覆盖会展示删除其他设置的警告与完整差异；编辑或切换方式后必须重新预览才能应用。用户可在外部编辑文件，再重新读取，以最新磁盘内容作对比并保留窗口中的编辑草稿。恢复备份和旧目录清理维持只读差异预览。

### 5.5 配置预览

宽度 920 px，最大高度为窗口 85%；顶部显示项目名和所选客户端。

- 使用按文件分组的前后差异视图；窄屏支持统一 diff。
- 新建文件明确标记“新建”，同名项标记“替换已有项”。
- 说明“将备份原始文件；保留其他 MCP 与设置”。JSON 格式变化在此说明。
- 不显示本地网关令牌，生成内容本身也不包含它。
- 主按钮“应用配置”；写入过程中不可重复点击。
- 结果按文件显示成功、未修改、失败或已回滚。
- 若预览后外部文件被修改，展示“文件已变化，请刷新预览”，不继续覆盖。
- 提供“查看备份”；恢复操作仍需要差异预览。

### 5.6 连接测试

在当前页展开结果面板：

```text
连接测试
✓ 找到当前项目运行记录
✓ 本地网关鉴权成功
✓ MCP 初始化成功
✓ 获取工具列表成功
工具：codegraph_explore

网关可用；请在 Codex / Claude Code 中确认实际会话连接。
```

步骤必须由真实探测驱动。工具名称为示例，以返回结果为准。测试失败停在实际失败阶段，提供重试与查看日志；不能为未执行步骤显示勾选。

### 5.7 日志页

- 工具栏包含等级筛选、关键词、暂停滚动、复制选中内容、导出当前项目日志。
- 行结构为时间、级别、阶段、消息，采用等宽字体，长行可横向滚动。
- 高流量使用虚拟列表，最多保留 2,000 行视图缓存。
- 用户向上滚动后暂停自动跟随，出现“回到最新”按钮。
- 清空视图不删除磁盘日志；文案明确“清空视图”。
- 切换项目后不混入前一个项目的延迟事件。

### 5.8 设置

只包含首版真实支持的项目：

- CodeGraph 入口：检测结果、选择文件、重新检测、版本。
- 索引任务并发数：默认 2，允许 1–4。
- 关闭窗口行为：隐藏到托盘 / 退出并停止所有实例。
- 应用数据目录：打开目录。
- 关于：应用版本、连接器版本、官方项目链接。

更换 CLI 入口后，运行项目提示“重启后使用新入口”；不会自动中断实例。操作系统开机自启不在首版设置中展示。

### 5.9 项目移除与重新定位

项目菜单包含重命名、编辑备注、重新定位、移除管理记录。

移除弹窗默认只删除管理记录，显示索引和客户端配置是否仍会保留；如用户选择一并移除受管配置，先走配置差异流程。首版不提供顺手勾选“删除整个项目”这样的操作。

重新定位先停止实例，验证新目录，再检测原配置。旧目录仍存在时，给出旧配置清理预览；新目录配置通过独立预览生成，不静默移动用户文件。

## 6. 状态与反馈规范

- 成功：Toast 持续 3 秒，关键结果仍保留在面板中。
- 错误：面板内持久显示，可展开详细信息，不依赖自动消失 Toast。
- 长任务：任务条显示阶段、耗时和取消；没有可靠总量时不显示百分比。
- 批量操作：显示每个项目结果及成功/失败数，失败项可单独重试。
- 运行数仅统计 Running；Starting 单独标注。
- 已配置不等于已启用，测试通过不等于用户客户端已连接。

建议错误文案：

```text
项目目录不存在。重新定位项目后再启动。
CodeGraph 启动失败。查看日志获取退出原因。
索引正在被其他进程使用。请先结束对应任务，再重试。
配置文件已被其他程序修改。刷新预览后再应用。
部分配置未能恢复。请查看逐文件结果和备份位置。
```

## 7. 可访问性与键盘

- Ctrl+K 聚焦项目搜索，Ctrl+N 添加项目，Ctrl+, 打开设置。
- Tab 按视觉顺序遍历；弹窗限制焦点，关闭后恢复到触发按钮。
- Esc 关闭非提交中的弹窗，不擅自取消后台索引任务。
- 状态变化使用适量 aria-live，日志不逐行打断屏幕阅读器。
- 图标按钮必须有文字辅助名称；Tooltip 不是唯一标签。
- 支持 125%/150%/200% Windows 缩放，操作区不能被裁切。
- 尊重减少动画偏好；禁止用无限闪烁表达错误。

## 8. UI 验收画面

实现时至少检查：空项目、CLI 缺失、多个项目、初始化进行中、运行实例、两个客户端已连接、配置差异、配置冲突、索引失败、日志长行、目录丢失、最小窗口和高 DPI。

前端开发可使用显式标注的 Mock 数据，但正式构建不得保留假项目或假连接状态。UI 原型与实际服务联调完成前，不宣称软件已可用。
