# 产品需求与范围

状态：设计草案，待技术验证；日期：2026-10-03。

## 1. 产品目标

让用户从桌面统一维护多个代码项目，为每个项目建立 CodeGraph 索引、单独启停 CodeGraph，并让该项目中的 Codex 和 Claude Code 使用正确的代码图谱。

核心体验是：添加项目 → 初始化索引 → 启动实例 → 配置客户端 → 验证连接 → 日常维护。

“独立实例”指一个项目有独立的 CodeGraph MCP 服务会话和进程树。上游可能启动解析工作进程，不能用操作系统进程总数等于一作为验收标准。

## 2. 已确定的约束

- 技术栈使用 Tauri 2、React、TypeScript、Vite。
- 源码与文档位于 `D:\projects\js\codegraph-desktop`。
- 首版提供中文桌面界面，保留后续国际化空间。
- 每个项目分别启停、使用独立 `.codegraph/` 索引，停止 A 不影响 B。
- 同一项目的两个 AI 客户端连接同一个受管实例。
- MCP 配置存放在项目目录，不自动修改用户级 Codex、Claude Code 配置。
- 原有配置必须可保留、可预览、可备份；失败不能报告为成功。

## 3. 首版功能

### 3.1 项目维护

- 使用系统目录选择器添加项目，支持别名、备注、搜索和排序。
- 展示项目路径、实例状态、索引状态、客户端配置状态。
- 路径规范化后去重；同一目录的大小写、符号链接和 junction 别名不能重复注册。
- 不同 Git worktree 作为不同项目；嵌套项目允许添加，但提示可能重复索引。
- 重新定位已移动项目：保留项目 ID，重新检查索引及配置，生成修复预览。
- 移除项目只移除管理记录；运行时先停止。索引和配置的删除是单独、明确的操作。

### 3.2 索引管理

- 初始化、增量同步、查看统计、重建索引。
- 显示实时日志和耗时；上游不提供进度时使用不定进度，不编造百分比。
- 使用已有索引时先读取状态，不能仅因为 `.codegraph/` 目录存在就认定索引可用。
- 每个项目同时只能有一个写索引任务；与运行实例的 watcher 进行互斥协调。
- 初始化失败保留诊断信息，可重试；不自动删除用户已有索引。

### 3.3 实例管理

- 逐项目启动、停止、重启。
- 展示实例 PID、运行时长、本地端口、已连接会话数及最近错误。
- 提供批量启动和批量停止；逐项目反馈结果，不以一个项目失败中断所有项目。
- 支持选择“应用启动时启动此项目”，默认关闭；这不等于操作系统开机自启。
- 关闭窗口默认进入托盘；托盘提供显示主窗口、停止全部、退出。
- 首版不提供独立 Windows 服务，完全退出应用后客户端连接不可用。

### 3.4 MCP 配置管理

- 分别或同时配置 Codex 与 Claude Code。
- 显示即将修改的文件、目标服务名、原有项冲突及差异预览。
- 使用固定服务名 `codegraph`，在项目配置文件内维护一个条目；URL 和鉴权信息绑定该项目，同名配置需预览确认。
- 生成 Streamable HTTP 直连配置；同项目客户端共用网关和 CodeGraph 实例，不启动额外 stdio 连接器。
- 展示“未配置、已配置、需修复、解析错误”，与“客户端实际连接成功”分开。
- 一键运行独立 MCP 探测；实际客户端信任与审批不能由写入文件替代。
- 移除配置时只删除本应用登记且仍匹配指纹的条目；已被手动修改的条目进入预览处理。

### 3.5 运行环境

- 检测 CodeGraph 安装位置和版本，支持手动指定受支持的入口。
- 第一版使用本机已有 CodeGraph，不内置安装器、不自动全局升级。
- 更换入口后重新检测；已运行实例保留旧启动信息，提示重启生效。
- 明确区分 CodeGraph CLI 不存在、版本不兼容、MCP 握手失败、索引不可用。

## 4. 典型使用场景

### 场景 A：首次接入一个项目

1. 添加项目目录并确认显示名称。
2. 检测 CodeGraph，初始化项目索引。
3. 启动该项目实例，完成后显示“运行中”。
4. 选择客户端，预览并写入项目配置。
5. 测试连接，显示服务信息和实际返回的工具名称。
6. 在项目中打开客户端，完成客户端自己的信任或授权步骤。

### 场景 B：同时使用两个项目

项目 A 与 B 分别拥有进程树、端口、索引和日志。A 的 Codex 连接不能查询 B 的代码；B 停止后 A 继续运行。拒绝跨项目参数是桥接层职责，不能仅靠提示词实现。

### 场景 C：同一项目使用两个客户端

Codex 和 Claude Code 分别建立独立连接器会话，连接同一个项目网关。网关复用一个上游 CodeGraph 会话，将并发请求隔离、排队并准确返回给来源客户端。

### 场景 D：恢复工作

应用重启后恢复项目列表、偏好和配置记录；不将上一次保存的 PID 直接视为存活实例。只对显式设置了自动启动的项目重新启动。

## 5. 首版不做

- 远程主机、SSH、WSL 内运行的 CodeGraph 管理。
- 多人协作、云端账号或远程公开 MCP 服务。
- 在项目之间共享一个全局代码图谱。
- 修改 CodeGraph 的解析算法或替代其索引器。
- 任意 MCP 服务器市场、通用终端、任意 Shell 命令执行面板。
- 为每个项目自动下载独立 CodeGraph 版本；后续可增加版本覆盖。
- 关闭桌面应用后仍独立存活的后台服务。

## 6. 验收原则

- 项目隔离、双客户端复用、配置不丢失是发布阻断项。
- “运行中”要求上游 MCP 握手与工具列表验证成功，不能只检查 PID。
- 索引统计来自实际 CLI 输出；连接数来自会话管理；无数据时显示“尚未获取”。
- 软件不能把“配置写入成功”“网关测试成功”“真实客户端已连接”混为一谈。
- 路径包含空格、中文和 Shell 特殊字符时必须正常工作。
- 所有重任务异步执行，界面在运行期间仍可查看其他项目。

## 7. 官方边界

Codex 支持可信项目下的 `.codex/config.toml`；Claude Code 的项目范围使用 `.mcp.json`，存在自身的项目授权流程。首版保留这些边界。[Codex MCP 文档](https://developers.openai.com/codex/mcp/) · [Claude Code MCP 文档](https://code.claude.com/docs/en/mcp)

CodeGraph 的本机 1.6.2 CLI 已确认支持 `serve --mcp --path <path>`。桌面 HTTP 网关及多客户端复用属于本产品新增设计，尚未验证成功，不是宣称 CodeGraph 原生提供 HTTP 服务。[CodeGraph 官方仓库](https://github.com/colbymchenry/codegraph)
